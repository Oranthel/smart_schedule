## 附录 A：数据模型

### A.1 实体总览

| 实体 | 说明 | 关键字段（节选） |
|---|---|---|
| `ScheduleItem` | 事项（统一抽象，子类型见下） | id, type, title, precision, fixedness, priority, start, end, recurrence, source_ref, confidence, status |
| `RoutineRule` | 基础作息规则 | id, title, weekdays, time_window, protected(false for 睡眠/用餐 per v1.1), valid_from, valid_to, exceptions[] |
| `Course` | 课程 | id, title, weekday, period, week_range, odd_even, classroom, teacher, fixedness=HARD |
| `Goal` | 宽泛目标 | id, title, period, est_hours, spent_hours, deadline, children[]（拆分子任务）, status |
| `ChangeLog` | AI 调整变更记录 | id, trigger, before, after, reason, affected_ids[], confirmed, reversible, created_at |
| `ImportBatch` | 导入批次 | id, source_type, raw_ref, parse_version, parsed_count, confirmed, created_at |
| `Conflict` | 冲突记录 | id, type(A/B/C), item_ids[], severity, resolution, status |

### A.2 事项子类型（`ScheduleItem.type`）

`FIXED`（固定事项）、`ROUTINE`（基础作息）、`COURSE`（课程）、`TEMP_ACTIVITY`（临时活动）、`TODO`（临时代办）、`GOAL_TASK`（目标拆分任务）、`REST_BUFFER`（休息缓冲）。

### A.3 关键枚举

- **精度级别 `precision`**：`EXACT | RANGE | PART_OF_DAY | DATE | WEEK | MONTH | DEADLINE | ANYTIME`
- **固定程度 `fixedness`**：`HARD`（硬性固定，不可自动移动）、`SOFT`（一般固定，可协商）、`FLEXIBLE`（灵活，可自动移动）、`OPTIONAL`（可选，ANYTIME）
- **优先级 `priority`**（数值越大越高，对齐 PRD 第八章）：
  - 100 取消/调课规则
  - 90 硬性固定事项（95 考试/交通，93 医疗预约，91 课程/会议/截止，90 用户标记不可移动）
  - 70 临时活动
  - 50 普通基础作息（含睡眠/用餐）
  - 30 灵活任务
  - 10 可选事项（ANYTIME）
- **状态 `status`**：`PENDING | SCHEDULED | IN_PROGRESS | DONE | SKIPPED | CANCELLED | OVERDUE | UNSCHEDULED`
- **置信度 `confidence`**：0.0–1.0，处理见附录 E

### A.4 睡眠/用餐的特殊处理（v1.1 决策落地）

- `RoutineRule.protected` 字段：睡眠/用餐 = `false`（普通基础作息，可被临时活动覆盖）。
- 引入 `SleepProtectionPolicy`：仅约束 AI 主动调度——调度引擎在排灵活任务时，将睡眠段标记为 `ai_no_schedule`，用户添加的 `TEMP_ACTIVITY` 不受此标记限制。
- 临时活动覆盖睡眠时，生成 `ChangeLog`（type=COVERS_ROUTINE），作息规则次日恢复（通过 recurrence 规则，不修改原规则）。

### A.5 引用与可追溯

- 每个 `ScheduleItem` 持有 `source_ref` → 指向 `ImportBatch` + 原始片段定位。
- 每次调整生成 `ChangeLog`，`ScheduleItem.last_change_id` 指向最近变更。
- 导入确认前事项 `status=PENDING`，不进入正式日程、提醒、小组件数据源。

## 附录 B：非功能需求（NFR）

| 维度 | 指标 | 说明 |
|---|---|---|
| 导入解析延迟 | 本地（CSV/文本结构化）< 2s；云端 LLM 解析 < 8s | 超时给出进度与降级提示 |
| 调度重排耗时 | 单日重排 < 500ms；周重排 < 2s | 端侧规则引擎，主线程外执行 |

## 附录 C：冲突形式化定义

调度引擎在"检测固定冲突"步骤按下列三类判定。仅这三类计入 `Conflict` 实体并须处理；临时活动覆盖睡眠/用餐不算冲突（按优先级直接覆盖 + 记 `ChangeLog`）。

### C.1 类型 A：固定事项相交
- 条件：两个 `fixedness=HARD` 的事项，时间区间 `[start_i, end_i)` 与 `[start_j, end_j)` 相交（含端点）。
- 处理：不自动决定，提示用户选择/调整其一；用户拒绝二选一时按第十七章"双标记+持续提示"。

### C.2 类型 B：转场缓冲不足
- 条件：相邻两事项地点不同，且前一项 `end` 到后一项 `start` 的间隔 < 所需缓冲（默认同地点 0min、不同地点 15min、需出门 30min，可配）。
- 处理：标记冲突提示；灵活方可移动时自动后移并告知，两方皆固定则提示用户。

### C.3 类型 C：灵活任务排入受保护段
- 条件：调度引擎拟将 `FLEXIBLE`/`OPTIONAL` 任务排入睡眠段，或拟压缩睡眠总时长。
- 处理：引擎层直接拒绝该排法（不产出），改寻其他空闲；无可用空闲则任务留为 `UNSCHEDULED` 并提示。此类型对用户不可见（引擎内部约束），仅当无法安排时上浮提示。

### C.4 非冲突情形（明确不计）
- 临时活动与睡眠/用餐相交：按优先级覆盖，记 `ChangeLog(type=COVERS_ROUTINE)`。
- 灵活任务与临时活动争抢同一空闲段：按优先级，灵活任务让位/移位，记 `ChangeLog`。
- ANYTIME 任务排不下：留为 `UNSCHEDULED`，不报冲突。

## 附录 D：AI 能力边界

把"AI"拆为两层，分别界定能力，避免黑盒。

### D.1 端侧规则引擎（确定性、离线、可解释）

| 能力 | 可做 | 不可做 |
|---|---|---|
| 调度 | 按优先级与空闲安排灵活任务、插入休息、计算保留空闲比例 | 移动硬性固定事项 |
| 冲突 | 检测 A/B/C 三类冲突 | 自动决定 A 类冲突 |
| 覆盖 | 临时活动覆盖睡眠/用餐并记 ChangeLog | 自主压缩睡眠（C 类拒绝） |
| 目标 | 剩余工时向空闲分配（平衡/积极模式） | 自主产生拆分子任务 |
| 精度 | 按时间远近套用精度展示规则 | 把宽泛目标伪装成确认事件 |

### D.2 云端 LLM（仅解析，非调度）

| 能力 | 可做 | 不可做 |
|---|---|---|
| 解析 | 文本/快速记录/OCR 结果 → 结构化事项（带置信度、待确认问题） | 直接写入正式日程（须经确认） |
| 拆分建议 | 为宽泛目标生成建议子任务序列（须用户确认） | 自主执行拆分 |
| 询问 | 不确定时返回待确认问题 | 静默臆测 |

### D.3 模式 × 动作 矩阵

| 动作 | 保守 | 平衡（默认） | 积极 |
|---|---|---|---|
| 移动灵活任务 | 仅明确允许 | 自动+告知 | 自动+告知 |
| 休息插入 | 不主动 | 自动 | 自动 |
| 时间分配（目标剩余工时） | 只建议 | 自动+告知 | 自动+告知 |
| 拆分建议 | 生成建议 | 生成建议 | 生成建议（主动） |
| 填充空闲（ANYTIME） | 不做 | 受保留比例约束 | 受保留比例约束 |
| 重大冲突 | 询问 | 提示 | 提示 |
| 远期重排 | 不做 | 受影响任务 | 未来几天 |

### D.4 离线降级

- 云端不可用：快速记录/导入解析 → `pending_parse_queue`；联网后批量解析，逐条按置信度门控提示确认。
- 端侧引擎始终可用，已确认日程的调度/冲突/提醒不受影响。

### D.5 数据最小化

- 云端调用 payload 仅含待解析片段（单条文本或单次 OCR 结果）+ 必要上下文（如当前日期、用户时区），不含全量日程、作息规则、课程表、历史。
- 云端不持久化用户内容；结果回写本地。
- 设置页"AI 使用信息"可查验最近 N 次调用的 payload 摘要。

## 附录 E：置信度阈值与处理策略

适用于导入解析、快速记录、OCR 结构化、拆分建议等所有 AI 产出的结构化结果。

| 置信度区间 | 处理策略 | 落库状态 |
|---|---|---|
| `≥ 0.85` | 直接写入正式日程（导入场景须经用户批次确认后生效） | `SCHEDULED`/`PENDING`(待批次确认) |
| `0.70 – 0.85` | 写入但标记 `needs_review`，首页与视图带"待复核"角标 | `SCHEDULED` + `needs_review=true` |
| `< 0.70` | 不写入正式日程，进入待确认列表 | `PENDING` 仅存于导入批次 |

- 阈值可在设置中调整（高级），默认值如上。
- 单条结果含"待确认问题"时（如结束时间不明、单双周不明），无论置信度多少都进待确认。
- 拆分建议的"建议"本身不参与置信度门控（它本就须用户确认），但子任务的预估工时带置信度。
- 手写计划 OCR：整体置信度 `< 0.70` 时整张图进待确认，不逐条写入。
