# 技术栈推荐与 v1 路线图

> 配套 `02-PRD-v1.1.md` 与 `03-技术附录.md`。本文给出选型理由（映射 PRD 硬诉求）与 v1.0/1.1/1.2 的可执行拆分。

---

## 一、技术栈决策

**主推：Android 原生（Kotlin + Jetpack Compose）**
**备选：React Native（Bare Workflow）**
**不推荐：Taro 多端小程序**

### 1.1 决策依据

PRD 的硬诉求几乎全压在平台原生能力上，而 v1 明确不含 iOS——这使"原生"的机会成本最低。

| PRD 硬诉求 | 出处 | 主推方案 | 适配度 |
|---|---|---|---|
| 桌面小组件 | 第十五章 | Jetpack Glance | 一等公民 |
| 闹钟 / 锁屏 / 稍后提醒 | 第十四章 | AlarmManager + ForegroundService + NotificationChannels | 原生最强 |
| 离线 / 本地优先 | 第十八章 | Room (SQLite) + DataStore | 一等公民 |
| 调度引擎（确定性可解释） | 第八/九/十章 | 纯 Kotlin 模块，可单测，WorkManager 后台重排 | 确定性可审计 |
| 自然语言 / OCR | 第五/十六章 | Retrofit 调云端 LLM，结果本地缓存 | 标准做法 |
| v1 不含 iOS | 第十九章 | 无需跨平台，省桥接成本 | 正面契合 |

### 1.2 备选场景

仅当"一年内必须上 iOS"才选 React Native（Bare Workflow + Eject Expo）。代价：小组件/闹钟需写原生模块（`react-native-android-widget`、`notifee` 等），集成成本高于原生；调度引擎可用 TS 共享，但原生能力仍是双份工作。

### 1.3 不推荐 Taro 小程序的理由

小程序的闹钟、锁屏、桌面小组件能力严重受限，与 PRD 第十四章/第十五章核心诉求冲突，会从根上削弱产品体验。

## 二、主推方案技术映射

### 2.1 模块划分

```
app/
├─ core/
│  ├─ scheduler/        端侧规则引擎（调度/冲突/休息/精度，纯 Kotlin，可单测）
│  ├─ data/             Room 实体 + DAO + Repository
│  ├─ ai/               云端 LLM 客户端 + 离线队列 + 置信度门控
│  └─ notifications/    通知/闹钟/勿扰/夜间开关
├─ feature/
│  ├─ home/             首页（日视图执行中心）
│  ├─ import/           导入与确认
│  ├─ plan/             基础作息/课程表/特殊日期管理
│  ├─ views/            日/周/月/年视图
│  └─ widget/           小组件（Glance）
└─ design/              Compose 主题/组件
```

### 2.2 关键技术选型

| 关注点 | 选型 | 备注 |
|---|---|---|
| UI | Jetpack Compose | 单 Activity + Navigation |
| 本地库 | Room + DataStore | Room 存事项/规则/变更；DataStore 存偏好 |
| 调度引擎 | 纯 Kotlin | 不依赖框架，便于单测与跨平台复用逻辑 |
| 后台重排 | WorkManager | 约束式后台任务，跨日后刷新 |
| 通知 | NotificationChannels + AlarmManager | 闹钟式提醒用 AlarmManager 唤醒 |
| 小组件 | Jetpack Glance | v1.1 起 |
| LLM 客户端 | Retrofit + OkHttp | 超时/重试/降级 |
| 离线队列 | Room 表 `pending_parse_queue` | 联网后 WorkManager 批量解析 |
| 加密 | SQLCipher（可选） | 本地加密存储 |

### 2.3 AI 架构（与平台无关，混合）

- **端侧规则引擎**：调度、冲突检测（附录 C 三类）、休息插入、精度控制、覆盖与优先级——确定性、离线、可解释。
- **云端 LLM**：仅 NL 解析与 OCR 结构化，分批调用，结果带置信度（附录 E）回写本地缓存。
- **数据最小化**：仅上传待解析片段，不传全量历史（附录 D.5）。

## 三、v1 路线图

### 3.1 v1.0 核心闭环（6–8 周）

目标：跑通第二十一章闭环（不含小组件/闹钟/OCR）。

**功能清单**
- 导入：文本 + CSV，导入确认（置信度门控、去重、整批撤销）
- 基础作息 + 课程表：手动录入 + CSV 导入；查看/修改/暂停/例外/删除（三档范围）；学期结束自动归档
- 临时活动 / 临时代办 / 宽泛目标 + 快速记录（在线解析，离线入队）
- 视图：日视图 + 周视图（四视图一致性先行落地这两视图）
- 调度：端侧规则引擎，平衡模式；冲突检测（A/B/C）；灵活任务自动移动；休息插入；保留空闲 ≥20%
- 目标：剩余工时向空闲分配（自动+告知）；拆分建议（须确认）
- 执行：完成 / 跳过 / 延后；撤销调整（窗口=跨日前或 24h）
- 提醒：本地通知（普通 + 重要）；勿扰；睡眠勿扰（仅闹钟级+显式夜间开关可打断）
- 数据：本地存储 + 离线可用；AI 调整说明（ChangeLog 透明可查）
- 隐私：数据最小化；"AI 使用信息"可查

**验收要点**：见 PRD 第二十章 + 评审报告决策表。重点：硬性固定事项不被自动移动；临时活动覆盖睡眠有标记且规则次日恢复；ANYTIME 排不下不计逾期；离线快速记录入队。

### 3.2 v1.1（4–6 周）

- 图片 / PDF 导入 + 课表 OCR（置信度门控；手写计划高置信度才写入）
- 月视图
- 闹钟式提醒 + 锁屏显示
- 桌面小组件：小尺寸 + 中尺寸（Glance）
- 保守 / 积极模式上线
- 特殊日期、调度偏好细化

### 3.3 v1.2（4 周）

- 年视图 + 大尺寸小组件
- 单双周 / 教学周完整支持
- 性能与稳定性优化（重排耗时、冷启动、存储清理）
- 模式调优（基于 v1.0/v1.1 真实使用数据）

## 四、v1.0 可执行需求清单（开发输入）

按模块给出 v1.0 必须实现的最小项，可直接作为任务拆分输入。

### 4.1 数据层（core/data）
- Room 实体：`ScheduleItem`、`RoutineRule`、`Course`、`Goal`、`ChangeLog`、`ImportBatch`、`Conflict`、`PendingParse`
- DAO 与 Repository；DataStore 偏好（调度模式、保留空闲比例、勿扰时段、阈值）
- 导入批次整批撤销；删除作息规则可恢复 7 天

### 4.2 调度引擎（core/scheduler）
- 优先级计算（附录 A.3 数值）
- 冲突检测 A/B/C（附录 C）
- 灵活任务安排 + 保留空闲比例
- 休息/缓冲插入（第十章规则）
- 精度展示规则（第十二章）
- 平衡模式行为（附录 D.3）
- ChangeLog 生成

### 4.3 AI（core/ai）
- 云端 LLM 客户端（NL 解析 + OCR 结构化，v1.0 仅 NL）
- 置信度门控（附录 E）
- 离线队列 + WorkManager 批量解析
- 数据最小化 payload 构造

### 4.4 通知（core/notifications）
- 普通/重要提醒；勿扰；睡眠勿扰例外
- 提前 5/10/15/30min 与自定义

### 4.5 功能页（feature/*）
- 首页：时间线、下一项倒计时、完成/跳过/延后、快速添加四入口、调整说明查看
- 导入：文本/CSV、确认页、待确认列表、去重
- 计划资料：基础作息管理、课程表管理、特殊日期、导入资料管理、调度偏好
- 视图：日视图、周视图

### 4.6 隐私与设置
- 本地加密（SQLCipher 可选）
- "AI 使用信息"查看
- 清空本地数据 / 删除原始资料

## 五、风险与缓解

| 风险 | 缓解 |
|---|---|
| OCR 识别率不稳 | 置信度门控 + 整张待确认；置于 v1.1，先用 v1.0 真实数据校准 |
| 调度引擎复杂度 | 纯 Kotlin 模块 + 充分单测；先平衡模式，保守/积极后置 |
| 小组件/闹钟原生成本 | 后置到 v1.1，避免阻塞 v1.0 闭环 |
| 云端 LLM 成本/延迟 | 分批、缓存、离线入队；仅传片段 |
| 范围蔓延 | 严格按路线图，v1.0 不含 OCR/小组件/闹钟/月年视图 |
